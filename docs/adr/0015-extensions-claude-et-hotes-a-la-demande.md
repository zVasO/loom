# Deux portes de plus : demander à Claude, et des hôtes accordés à l'usage

Une veille techno en extension (ADR-0011, ADR-0012) bute sur deux murs : elle veut un résumé du matin écrit par Claude, et elle lit des flux que l'utilisateur ajoute après l'installation — des hôtes que son manifeste ne peut pas nommer. Le principe ne change pas : ce qui est propre au besoin vit dans l'extension, Loom n'ouvre que des portes génériques, chacune sous permission. Décision : deux ajouts au pont. **Claude** (`"claude": ["complete"]`, `loom.claude.complete`) : Loom lance `claude -p` avec le compte Claude Code de l'utilisateur, en texte seul — `--tools ""`, `--strict-mcp-config` sans configuration, `--disable-slash-commands`, hooks désactivés, `--no-session-persistence`, un prompt système (celui de l'extension, ou celui de Loom) qui remplace la persona d'agent —, dans un dossier temporaire vide supprimé ensuite, le prompt sur l'entrée standard (jamais dans argv), sans les variables qui relient un agent à Loom ; l'appel marche en arrière-plan ; une requête à la fois par extension, trente par heure, deux pour toute l'app ; délai de 10 s à 5 min ; prompt de 100 000 caractères au plus ; modèles `haiku`, `sonnet`, `opus` ou celui par défaut ; erreurs `unavailable` (claude absent, déconnecté, trop ancien, en erreur) et `timeout`, deux codes nouveaux. **Hôtes à l'usage** (`"optionalNetwork": true`, `loom.network.request/granted/revoke`) : l'extension demande des hôtes exacts quand l'utilisateur ajoute un flux ; seulement au premier plan, comme un lancement ; Loom ouvre une feuille, une case par hôte ; dix par demande, soixante-quatre par extension ; gardés dans `state.json` à côté de l'autorisation (jamais dedans : celle-ci ne dépasse pas le manifeste), conservés aux mises à jour, effacés avec l'extension, retirés un par un dans les réglages — la page entend `network.changed` ; `http.fetch` vérifie chaque URL contre les hôtes du manifeste plus ceux-là. Alternatives rejetées : une clé d'API Anthropic tenue par l'extension (un secret de plus à gérer, une facture à part, rien de ce que Claude Code sait déjà faire) ; lancer une session Loom (une confirmation à chaque fois : pas de résumé du matin, et la réponse reste dans un terminal) ; `"network": ["*"]` (l'extension pourrait parler à n'importe qui) ; un `feeds.fetch` natif (un besoin particulier dans le cœur, et l'URL seule peut déjà faire fuir des données) ; un proxy RSS tiers (une fuite et une dépendance).

## Consequences

- Les deux permissions suivent les règles de l'ADR-0011 : montrées en clair au consentement — celle de Claude dit qu'elle compte sur le forfait de l'utilisateur —, redemandées si un manifeste les ajoute. Un Loom plus ancien refuse un manifeste qui les porte ; `loomApi` reste à 1.
- `ExtensionPermissions` n'encode plus que ce qui est posé : un `state.json` écrit par ce Loom reste lisible par un plus ancien.
- Un run de Claude ne laisse pas de transcription : il n'apparaît pas dans les coûts de Loom ; l'extension reçoit `costUsd` et peut l'afficher.
- Les fichiers de réglages de l'utilisateur (`CLAUDE.md`, permissions) sont encore lus : sans outil, ils ne donnent accès à rien.
- Désactiver, mettre à jour ou supprimer une extension tue ses runs de Claude en cours et ferme sa feuille d'hôtes (refus).
- La visite guidée d'une PR passe par le même exécuteur (`ClaudeOneShot`), avec les outils de Claude Code dans le dépôt : son diff part sur l'entrée standard, plus dans argv.
- Exemple livré : `Examples/extensions/tech-watch/` utilise les deux ; rien de la veille n'est dans Loom.
